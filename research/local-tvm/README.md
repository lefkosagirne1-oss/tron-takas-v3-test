# Isolated local TRON/TVM validation — 2026-10-30

This suite runs the unchanged guarded baseline and guarded optimized artifacts from ../mainnet-cost-guarded on java-tron GreatVoyage-v4.8.2.4. It does not connect to, sign for, or deploy to Nile/Mainnet. Results are private-chain evidence, not a security audit or a Mainnet fee quote.

## Runtime and isolation

- Official release FullNode.jar SHA256:709423e8d14ccba391daeef7aa78bb5f41a1b69559cc867346beacbd6aae39c9.
- Separate Temurin Java8u504 JRE, archive checksum verified against official release checksum file. System Java unchanged.
- TRON-solc0.8.31 checksum verified; prior production-window artifacts are used without editing deadlines.
- Fresh local-only test accounts generated by init.cjs; secrets/config/database/logs stay outside Git. No user's key is used.
- Public seeds, active/passive/fastForward peers, discovery and DNS tree URLs empty/disabled. Distinct P2P id297102924. Native loopback.c wrapper forces Java bind addresses to loopback and rejects non-loopback TCP connect. listnodes must be empty.
- Every run uses its own database path. Java child and HTTP client are launched from the same process/tool network context. Only its own child is terminated.

## Resolved infrastructure problems

1. Docker absent/Java17 incompatible with amd64 FullNode: installed separate verified Java8.
2. Separate tool calls could not reach prior node; shared database also caused LOCK errors: launch Java inside harness with unique -d directory.
3. Readiness uses direct local fetch and NO_PROXY; IPv4 stack explicitly selected.
4. An isolated node with zero peers rejects broadcasts by default with NO_CONNECTION: node.rpc.minEffectiveConnection=0 is set only in private test configuration.
5. TronWeb balance convenience API hit disabled walletsolidity HTTP endpoint (405): use Fullnode wallet/getaccount explicitly.

## Reproduce

Install repository dependencies and tronweb@6. Run setup-runtime.py to download official Java8/TRON/compiler components into /tmp/takas-local-tvm, then compile loopback.c with gcc -shared -fPIC -ldl. Run node research/local-tvm/init.cjs to generate fresh ephemeral accounts/config. Run node research/local-tvm/run.cjs. This takes at least15minutes for the production900/300second deadlines; no reduced-window artifact is used. Do not display or commit /tmp/takas-local-tvm/accounts.json, private.conf or raw node logs.

## Test invariants

Each baseline/optimized swap uses a separate fresh mock token, fresh swap contract and equal amounts. This is essential: reusing a token can make the second recipient balance nonzero, reducing token SSTORE cost by15000Energy and falsely suggesting an optimization benefit. initial-results from that unequal-state exploratory run are deliberately excluded from final comparison.

The suite asserts exact20,000,000raw token delivery,49TRX native delivery,1TRX commission (adjusting initiating account balance for its receipt fee), zero remaining escrow, manager-only finalization, premature refund/finalize rejection and duplicate-finalize rejection. Candidate timeout deals use exact production bytecode and real private-chain elapsed time: one50TRX deposit waits900seconds; another50TRX/mock-token deal waits300seconds after second deposit. Refunds must return full gross deposit, leave no commission, reject late finalize/double refund, and leave zero escrow.

## Cost interpretation

Measured local Energy is converted using the separately fetched Mainnet getEnergyFee. Local Bandwidth burn rate/free allowance differ from Mainnet, so derive bytes from net_usage or local net_fee/local_getTransactionFee before applying Mainnet getTransactionFee. Do not copy actual local TRX fee totals as Mainnet totals. Mock token mint/deployment are test-fixture costs and excluded from swap total. A real token's implementation, recipient balance, allowance and Mainnet Dynamic Energy can change costs; this suite is not a USDT quote.

See results.json and summary.json for final measurements/check status. Production release still requires user's planned live Nile validation and separate security review; no live frontend or artifact is changed by this branch.

## Final outcome

PASS: both equal-state swaps and exact settlement/commission balance assertions; unchanged production900-second single-deposit refund and300-second dual-deposit refunds, all gross amounts returned and escrow emptied.

Seven additional negative cases were verified with actual local transaction receipts reporting REVERT: duplicate finalize, duplicate refund, expired finalization, empty deal finalization, premature refund, only-one-deposit finalization and non-manager finalization. Receipt hashes and Energy are in results.json. These deliberately failed local test transactions are excluded from normal successful-swap fee totals.

Test-method correction: nonpayable TronWeb method.call() throws at SDK level and is NOT valid proof of a TVM guard. Exploratory constant-call responses also varied/omitted revert fields. Final negative evidence uses mined private-chain REVERT receipts, and run.cjs now uses the same receipt-backed method. verify-negative.cjs documents the independent verification pass; it requires TVM_TEST_DATA_DIR for the existing isolated ledger. A node restart rolled back an unconfirmed tip in that ledger, so verification first restored/asserted the refunded state before attempting duplicate refund. That restoration is labelled separately and is not counted as duplicate-refund proof or as a normal swap fee. The harness now waits an additional block before terminating its own child.

No Nile/Mainnet transaction was signed or broadcast, no real TRX was spent, no production file/artifact changed. Local peer list was empty. This is tested private-TVM behavior; user-planned live Nile validation and independent security review remain separate release gates.
